# Dependency extraction

`slopguard.extractor.extract_dependencies` is a pure, offline extractor. Give it `ChangedFile` values containing the file path, base text, and head text. It compares the two versions and emits only added or replacement dependencies from the head version. Deletions and unchanged dependencies are ignored. Callers can pass `local_modules` to exclude first-party module names; `local_modules_from_paths` builds this set from repository paths and an optional project name.

Each normalized result conforms to the SG-01 dependency-result schema. At extraction time, `registry_exists` is `null`, evidence and similarity candidates are empty, and the score is a neutral placeholder. Later registry and scoring stages must populate those fields before making policy decisions. `source_locations` records the file, 1-based line, and source kind; duplicate package names are emitted once with all their locations.

## Supported syntax

- Requirements and constraints files named with `requirement(s)` or `constraint(s)` and ending in `.txt` or `.in`, plus any `.txt` or `.in` file under a `requirements` directory. PEP 508 names, extras, version specifiers, markers, comments, inline comments, continued logical lines, and per-requirement `--hash` options are supported.
- PEP 621 `project.dependencies` and `project.optional-dependencies` arrays, PEP 735 arrays in `[dependency-groups]`, and `[build-system].requires` in `pyproject.toml`. Dependency-group `{include-group = "..."}` references are skipped because they are group references, not package names.
- Python `import` and absolute `from` statements found by parsing the complete base and head syntax trees. Imports inside strings, relative imports, `__future__`, standard-library imports, and known local modules are excluded. Known import names and dotted prefixes are mapped to distributions, including `cv2` to `opencv-python`, `PIL` to `Pillow`, `yaml` to `PyYAML`, and `google.protobuf` to `protobuf`. An unmapped ordinary import is emitted as an import-only finding; downstream scoring should treat import-only findings as warn-only. Unmapped `google`, `azure`, `zope`, and `backports` namespace roots produce a warning instead of a guessed package name.
- Changes in `setup.py`, `setup.cfg`, and `Pipfile` produce a manual-review warning; their dependency syntax is not interpreted, and `setup.py` imports are not treated as dependencies.

Direct URLs, VCS/editable requirements, include directives, dynamic dependencies, Poetry dependency tables, malformed requirements, and malformed TOML are skipped with a file/line warning when their changed lines can be located. Global package index options receive a dedicated manual-review warning; supported option-only flags that do not identify a package are ignored. Included requirements files must be passed separately as changed files. A head Python syntax error produces a warning; if only the base file cannot be parsed, its imports are treated as empty and a warning is emitted. The extractor does not access the network, resolve markers, infer imports from unchanged code, install packages, or execute project code.

To keep processing bounded, non-Python changed files are skipped with a warning when their combined base and head content exceeds 2,000 lines or 1,000,000 characters. Python files use AST comparison and are subject to the 1,000,000-character cap but not the line cap. The extractor stops and returns one warning without partial candidates when the input exceeds 1,000 changed files or 20,000,000 combined base/head characters.
